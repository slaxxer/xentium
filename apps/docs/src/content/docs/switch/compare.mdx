## Why communities choose Xentium

<div class="xd-why">
  <div class="xd-why__item">
    <strong>Design every page, live</strong>
    <span>Theme Studio arranges blocks on every page, the header and footer included, in a live preview of your site. Colours, fonts and layouts publish together when you're ready, and you can roll back from the history.</span>
  </div>
  <div class="xd-why__item">
    <strong>Themes you can trust</strong>
    <span>A Xentium theme is pure data: colours, fonts and layouts. It can't run code on your server, so trying a new theme is never a security decision.</span>
  </div>
  <div class="xd-why__item">
    <strong>One community, not a plugin stack</strong>
    <span>Articles, profiles, notifications, progression ranks and moderation are part of core. The forum and other official plugins plug into the same members, permissions and editor.</span>
  </div>
  <div class="xd-why__item">
    <strong>Moderation that thinks ahead</strong>
    <span>Reports, warnings and bans in one place, plus abuse detection for rapid logins, multi-accounts, registration bursts and ban evasion. It opens a case for a human and never acts on its own.</span>
  </div>
  <div class="xd-why__item">
    <strong>Sign-in members actually use</strong>
    <span>Passkeys, sign-in links by email, and Google, GitHub and Discord, built in. Every access rule is a permission you can see and change in the admin panel.</span>
  </div>
  <div class="xd-why__item">
    <strong>Open and yours</strong>
    <span>The core is open source under MIT. You host it, your data stays on your server, and the update check is anonymous. Paid official plugins extend it, and a lapsed licence never takes your site down.</span>
  </div>
</div>

## Is Xentium right for you?

<div class="xd-fit">
  <div class="xd-fit__col xd-fit__col--yes">
    <strong>A great fit if</strong>
    <ul>
      <li>you want a forum and articles under one roof, with one set of members</li>
      <li>you care how your site looks and want to change it without touching code</li>
      <li>your moderators need better tools against spam, multi-accounts and ban evasion</li>
      <li>you want an open-source core and your data on your own server</li>
      <li>you can run a small Linux server (or have someone who can)</li>
    </ul>
  </div>
  <div class="xd-fit__col xd-fit__col--no">
    <strong>Not the right fit yet if</strong>
    <ul>
      <li>you need a gallery, a calendar or authenticator-app codes today</li>
      <li>your site has to stay on shared PHP hosting, or you want it hosted for you</li>
      <li>you rely on specific add-ons from your current platform that Xentium doesn't have</li>
      <li>you need a platform with many years of production behind it right now</li>
    </ul>
  </div>
</div>

## Switching is free

Our migration tools are free and open source. They bring your members, forum structure,
threads and posts over, and always start with a dry run that writes nothing.

| Coming from | Migration tool | Members keep their passwords |
|---|---|---|
| [WordPress](/switch/from-wordpress/) | ✓ | – they reset once |
| [phpBB](/switch/from-phpbb/) | ✓ | ✓ |
| [XenForo](/switch/from-xenforo/) | ✓ | ✓ for standard password hashes |
| [WoltLab Suite](/switch/from-woltlab/) | ✓ members, articles and forum | ✓ |
| [vBulletin](/switch/from-vbulletin/) | ✓ versions 3 to 6 | ✓ |

Each platform's page covers what you gain, what you give up, exactly what moves over and
the steps to switch. The technical reference is
[Migrating from another platform](/guides/migrating/).

## Questions people ask

<details>
<summary>Is Xentium ready for my community?</summary>

Xentium is in a closed alpha. It works and we build on it every day, but no community runs
on it in production yet, so expect rough edges and changes between releases. If you're
starting a new community or can move at your own pace, now is a good time to try it on a
test server.

</details>

<details>
<summary>Is it free?</summary>

The core is free and open source under the MIT licence: articles, members, profiles,
moderation, Theme Studio, the plugin engine and more. We also offer paid official
plugins that extend it. A plugin licence that lapses never breaks your site.

</details>

<details>
<summary>What do I need to host it?</summary>

A server where you can run Node.js, PostgreSQL and Redis. A small VPS is enough to start.
The installer sets up the database and Redis for you (see
[Installing Xentium on a server](/admin/installing/)). Shared PHP hosting won't work, and
we don't offer hosting ourselves.

</details>

<details>
<summary>What happens to private messages and attachments?</summary>

Private messages come over as conversations, from phpBB, XenForo, vBulletin and
WoltLab, when the messaging plugin is enabled on your Xentium site. Each conversation
goes only to its original participants, ones a member had deleted arrive archived, and
everything counts as read. Attachments stay where they are: imported posts link to
them, so keep the old files online or copy them over. The migration report lists
everything that was skipped.

</details>

<details>
<summary>Will my old links keep working?</summary>

Yes, if you let the migration tool write redirects. Xentium's URLs differ from your old
platform's, so with `--redirects` the tool writes an nginx file (and a CSV for other web
servers) that sends every old thread, post, board, member and article link to its new
page with a permanent redirect. Search engines follow those and carry your rankings over.

</details>

<details>
<summary>Who builds Xentium?</summary>

A small, independent team. Everything we know is in these docs, and the code is on
[GitHub](https://github.com/slaxxer/xentium), where you can follow along and open issues.

</details>
